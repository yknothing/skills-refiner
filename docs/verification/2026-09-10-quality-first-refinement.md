# skills-refiner 质量优先改进验收

日期：2026-09-10。原版基线：`580ee1c4ef6bde931cb72678c78bafe598246026`。

## 范围与交付

本轮落实三项工作：质量优先的评判标准、可直接使用的 Skill 与系统设计改进指导、原版与候选的限定对比及独立评审。候选仍在源仓库，未全局安装。

- `skills-refiner` 明确保留和提升质量、能力优先，token 成本其次；支持必要的知识补充、局部简化和有依据的零修改。
- 改进建议要落实到触发条件、具体行为、保留要求、资源与消费者，以及接受改动所需的观察。补足跨阶段交接、已授权工作承接、实施缺口与验证缺口的区分，以及全库任务的有限验收。
- 保留 Stage 1 / Stage 2 的源审查与目标整合边界；复用有效的既有审查，不强制重开完整审计。移除固定报告结构、评分卡和问题数量要求。
- 将审慎演进、部署约束和创建工具协作放在按需参考中。部署开场句调整为复用相关审查；从 `Before proposing` 起的部署条款正文逐字保留，来源、身份、完整资源集、安装资格、回滚与宿主证据要求不变。
- 同步 refiner 的旧案例与锚点，新增 10A–10D、11A–11D。`skills-appreciation` 仍使用自己的 rubric 和锚点。

没有修改其他四份 Skill 正文、安装脚本、控制协议、宿主配置或全局安装目录；没有增添运行依赖。[ADR-0009](../adr/0009-conservative-skill-evolution.md) 仅更新局部实施状态，保持 `Proposed`。本轮不等于该 ADR 的阶段 A 全部完成，也未实现阶段 B/C 的协议、校验与展示。

## 对比设计与证据边界

比较单位是给定资料下的审查与设计答复，不是实际修改、部署或完整多模型工作流。

| 输入 | 来源与用途 |
|---|---|
| 10A–10D | 根据会话情境重建的四个独立决策快照：具体设计指导、承接授权、有限验收、部署交接。不是原会话的完整重放，也不证明某条 Skill 导致过真实会话结果。 |
| 11A–11D | 新建的合成校准案例：评审修复掩盖回归、增加指导带来质量改善、通过计划间接起作用、合理保持现状。作者参与设计这些案例，因此不称为盲留出集。 |
| 02、08 | 候选冻结后执行的既有回归输入：README 证据不足、API 文档 Skill 设计审查。已核对两份 `Input` 与原版基线一致；执行者未看到 Expected behavior 或锚点。 |

原版、初版候选 `candidate-r1` 和修订候选 `candidate-r2` 分别冻结完整 Skill 与引用资源。每版按 10A–10D、11A–11D、02/08 分为三个独立执行批次。各批次使用新的执行 agent；批内共享上下文，只要求隔离目标事实，不能称为每例独立新会话或多次重复试验。

执行 agent 均使用父任务配置且未显式覆盖模型或 effort；工具未提供可核对的 provider 路由、精确 token 用量、费用或完整计时。可控的输入、权限与工具限制保持相同，不能据此宣称供应商执行条件完全可观测。提供的目标宿主、测试和业务结果是题目证据，执行者未实际复现这些目标操作。

原始答复先保存，之后再评分；不把评审修订后的答复覆盖回原记录。匿名评审每例使用独立置换的 X/Y 标签，并且只获准读取输入、rubric、锚点和答复，未获得版本映射或 Skill diff。匿名降低标签偏好，但措辞风格仍可能透露版本，不能视为完美盲法。

## 发现、修正与复验

| 发现 | 处理与边界 |
|---|---|
| 独立源码评审发现 11A 锚点把 `Provider usage` 的 12% 降幅写成金额成本降幅 | 在评分前修正锚点，明确单位与金额未知；题目输入和已生成答复未变。 |
| 完整 diff 评审发现 evals README 把 refiner 的无数量要求泛化到了 appreciation | 将说明限定为 `skills-refiner`，保留 appreciation 原评测范围。 |
| 终审发现报告将部署参考的引导句调整也算作逐字保留 | 精确限定逐字比较的起点，并单列引导句的续跑适配；部署不变量未改变。 |
| 根任务复核发现 case-08 的 Expected behavior 预设部分风险为缺陷，旧锚点还从摘要断言测试缺少边界覆盖 | 区分观察到的冲突和待验证风险；摘要只能支持所报告的案例，不能证明没有其他覆盖。不强制扩协议支持或拆 Skill；`Input` 未变。 |
| 初版候选 11A 正确拒绝全局替换，但两次把未知单位的 usage 写成完整流程模型成本 | 判为局部证据表述回归。原版在这一点上更准确；保存失败，不用正确的总体决策抵消。补充通用计量规则：保留原单位，未定义的 usage 不得改称 token 或金额。 |

最后一项只改动 `references/conservative-evolution.md`，重新冻结为 `candidate-r2`，重新生成全部十例答复。原版答复保持冻结复用，因此最终比较并不是第二次原版重复运行。修订后在既有失败题上的成功只能说明该样本没有再次出现相同错误，不能证明规则的因果贡献或未知任务泛化。

case-08 锚点的证据范围澄清发生在最终匿名评审期间，原锚点一并保存；评审者重新读取后确认，其原判断已经遵循这个证据边界。该澄清没有修改输入、指导资源或原始答复。

## 逐例结果

初版八例匿名比较为七例实质相当、11A 原版更好；11A 的计量错误作为候选局部回归保留。初版额外的 02/08 答复也已保存，但未计入这一轮八例评分。

最终候选与冻结原版的十例匿名比较如下。两版均完成必要决策，未发现关键失败或实质遗漏；以下优劣比较来自具体改进的可用性和证据精度，不按篇幅打分。

| 案例 | 最终候选相对原版 | 依据 |
|---|---|---|
| 02：README 证据不足 | 更好 | 将入口、选择和安装说明改进落实到具体文本、使用条件与验收观察，同时保留实现未知。 |
| 08：API 文档 Skill | 更好 | 提供可合并的替换指导，细化取证、格式完成条件与更新边界，仍限定测试摘要的证据范围。 |
| 10A：规划与实施协作 | 实质相当 | 均能复用批准计划、保留兼容性资源并提供实际替换指导。 |
| 10B：实施与验证分工 | 实质相当 | 均区分契约断点、未授权 Adapter 修复和交给其他人的验证，不把实现缺口改称待评测。 |
| 10C：全库有限验收 | 实质相当 | 均复用局部接受证据、补剩余覆盖与三条任务链，明确停止条件。 |
| 10D：全局安装交接 | 更好 | 完整成员及来源资格判断均正确；候选对正文读取、加载与收益之间的证据边界更明确。 |
| 11A：修补掩盖质量回归 | 更好 | 未再把未知单位 usage 写成费用；进一步给出跨规划、执行阶段恢复必要支持的具体指导。原版总体决定同样正确。 |
| 11B：更长但质量更好 | 实质相当 | 均支持预算范围内的质量改善，不将字符或费用误当 token，也不擅自安装。 |
| 11C：通过计划间接贡献 | 更好 | 保留引用与实际依赖，限定优化条件，避免从给定材料直接要求修改扫描器。 |
| 11D：合理保持现状 | 实质相当 | 均保留正确边界，不强造问题、评分卡或额外测试。 |

根任务复核原始答复后接受上述有限结论：最终候选在五例中观察到具体质量优势，另五例没有实质差别，未发现实质回归。可完成这批源指导与决策案例的设计验收；成本效果未决。

候选答复在修订后重新采样，两轮匿名评审由不同评审者完成。不能把前后优胜数量的变化归因于新增计量句，也不能从十例推出普遍提高或稳定等效。仍有非阻断的完善空间：10B 的 Adapter 恢复安排较概括，10D 未显式单列 following 证据层。它们没有导致越权、伪造运行成功或推翻本例决定，本轮不据此扩成新的任意优化批次。

- 先前尝试的 Gemini CLI 全局扫描未取得可用完成结果；本轮采用上述限定原生解析器检查。历史 Codex CLI 配置解析阻断保留在 ADR 的带日期记录中，本轮没有重新证明它已修复。
- 五份全局已安装 `SKILL.md` 入口仍与本轮原版基线一致。此核对只证明五份入口未替换，不是对全局每个资源、投影和宿主的完整部署验收。没有注入或剥离 canary。

## 复核与回退

原始输入、三个版本的完整指导资源、30 份未修补答复、加载记录、匿名映射、评审记录和检查结果保存在[证据文件](2026-09-10-quality-first-refinement-evidence.json)。文本均附 SHA-256；机器核对摘要只验证记录完整性，不代替语义评审。复评时先隐藏版本映射、原指导和先前评分，再按相同输入与锚点评估答复。

原始加载记录中的临时路径仅是历史标识；所需正文已随证据归档，复核不依赖那些临时目录继续存在。

收尾检查通过：71 条原始文本记录的长度与摘要、10 个输入和 30 份答复计数、匿名文件与映射绑定、原版与 Git 基线一致性、最终包与当前源文件一致性。本次 22 份 Markdown 的 29 个本地文档链接有效，`git diff --check` 通过；案例中粘贴的目标输入按测试资料处理，不把其中的示例路径当仓库链接。

独立终审再次核对了上述归档、最终源文件、匿名映射与逐例报告，确认本轮限定范围没有阻塞项。该终审验证记录一致性，未把它计作新的模型运行或宿主验收。

源仓库回退可以恢复上述基线中的本次已跟踪文件，并移除本次新增文件；应使用明确文件列表，保留已有无关改动。因为未更新全局安装，本轮不需要执行安装回滚。后续发布仍需走现有合格来源与部署机制。

本轮保留原先已有的两处无关未跟踪内容：`docs/adversarial-product-pk/2026-07-23-broken-link-hygiene/` 和 `docs/verification/2026-07-23-broken-link-hygiene.md`。未将它们纳入本次审查或改动。
