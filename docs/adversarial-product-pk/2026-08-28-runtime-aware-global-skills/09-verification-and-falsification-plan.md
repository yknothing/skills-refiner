# 09 — Verification and Falsification Plan

## Before promotion

1. Re-run source-attestation and exact-object negative tests.
2. Re-run the complete ProdCraft successor/history suite.
3. Re-run Panorama normalization/CLI suites, including installer-declared lifecycle typing.
4. Compare repository and installed governance Skills payload; explain only intentional fixture exclusions.
5. Run fresh collection list, full provenance scan, runtime profile status and native probes.
6. Regenerate Panorama only after current evidence is recorded; hash the final owner-private outputs.
7. Verify frontmatter names, description budgets, references and static runtime contracts for all published governance Skills.
8. Confirm protected user-owned untracked files were not opened, edited or staged.
9. Bind the five exact plan hashes to an Owner decision.
10. For a live latest upgrade, force direct successor rejection on predecessor drift, then verify repair/predecessor quarantine
    identity continuity before applying the successor.
11. Re-run collision negative tests and confirm the live successor reports no false `PRESERVED_COLLISION_SET_CHANGED`.

## After promotion

- Any collection, policy, runtime config, executable or discovery-root change invalidates the affected runtime evidence.
- Any manual deletion/addition or INDEX rewrite must appear as fresh status/Panorama drift.
- Any future installer wrapper must record immutable candidate resolution in its own operation-bound record; it must not rewrite
  third-party receipts to manufacture authority.
- Any context-saving claim requires fresh-session comparative measurement.
- Any cleanup requires a separate, exact, identity-bound decision and plan.

## Stop conditions

Stop promotion on P0, unresolved P1, unparseable/blocking collector output, unexpected filesystem mutation, controller drift, or a
claim ledger statement whose supporting evidence is stale.
