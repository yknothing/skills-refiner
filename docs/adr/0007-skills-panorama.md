# ADR-0007: 技能全景（skills-panorama）

- **Status:** Accepted with limitations  
- **Date:** 2026-07-22  
- **Deciders:** Product owner (host machine) + skills-refiner maintainers  
- **Depends on:** ADR-0001（观测边界）；ADR-0003 / ADR-0006（控制面与事实分域）；既有 `skill-scan` 与 collection/status 只读输出  
- **Related:** `skill-hygiene`（健康判断与处置）；`skill-debug`（探针观测）；grilling 会话共识（2026-07-22）  
- **Review level:** Owner grilling → 决策锁定；实现前可另开对抗性评审

## 1. Decision

skills-refiner 增加能力 **技能全景（`skills-panorama`）**：对「你本机已部署的 Agent Skills」做只读全景——先看清拓扑，再对照意图与现实是否一致。

| 维度 | V1 决定 |
|---|---|
| 主目标 | **拓扑地图**：源目录有什么、各 Agent 里出现了什么、链接是否完好、有无命名冲突 |
| 次目标 | **证据对照**：控制清单批准启用的，与磁盘/投影现实是否一致 |
| 用量 | **不要求**；无激活/加载证据也可交付全景 |
| 形态 | **脚本/CLI 出事实快照** + **薄 skill 入口**解说与分诊 |
| 写权限 | **只读**；不删除、不改软链、不改控制清单 |
| 事实来源 | **编排现有收集器**；不新增第二套磁盘遍历算法 |
| 对外文案 | **中文主界面**；JSON 保留英文键；文末附字段对照 |

禁止把多层事实压成一个「已安装」或「就绪」总标签（与 ADR-0003 / ADR-0006 分域一致）。

## 2. Why this exists

用户痛点不是「再多一份健康打分」，而是：装了几十上百个 skill 之后，**说不清本机到底长什么样**。

现有分工已清楚，但缺一张「摊开的地图」：

| 已有能力 | 强项 | 不替代全景的原因 |
|---|---|---|
| `skill-scan` | 收集拓扑、哈希、链接等事实 | 面向机器/审计，不是人话全景与分诊入口 |
| `skill-hygiene` | 健康判断与处置建议 | 岗位是治理，不是第一眼拓扑 |
| `skill-debug` | 发现面探针与观测面板 | 偏观测，不是安装拓扑权威 |
| pack / reconciliation catalog | 部署意图 | 意图 ≠ 磁盘实况 |

全景的独特价值：**对齐多层 → 人话缺口分类 → 中文报告 → 低打字分诊**；不是第二个扫描仪，也不是第二个 hygiene。

## 3. Product identity

### 3.1 命名

| 对外 | 值 |
|---|---|
| 中文名 | 技能全景 |
| Skill 标识 | `skills-panorama` |
| CLI（建议） | `skill-panorama`（或仓库统一入口下的 `panorama` 子命令） |
| 报告标题 | 已安装 Agent Skills 全景 |

### 3.2 岗位边界

```text
技能全景          → 看清 + 分诊（交给谁）
skill-hygiene     → 评估 + 可变操作建议（需二次确认）
skill-debug       → 探针/观测补充（非 V1 必需）
```

硬规则：全景 **不得** 输出删除、修改软链、修改控制清单的具体命令；最多引导用户进入 `skill-hygiene`（或调整 Agent 覆盖范围等只读/配置类下一步）。

## 4. Scan universe（V1）

### 4.1 纳入

1. **全局技能源目录**（如 `~/.agents/skills/`，以及受管 collection 的物理根，以现有收集器已覆盖范围为准）  
2. **Agent 投影目录**（默认见 §5）  
3. **控制清单 / 控制面意图**（reconciliation catalog 等，只读对照）

### 4.2 默认不纳入

- 任意项目仓库内的 skills（authoring 副本）  
- 全 home 启发式搜索所有 `SKILL.md`  
- quarantine / shelf 作为默认主表（若现有 status 已暴露，可在 JSON 附录保留，不进默认八类主导航）

项目级扫描若需要，须 **显式开关**，属 V1 之后。

## 5. Agent 覆盖与交互配置

### 5.1 默认清单

默认勾选三件套（目录存在才参与投影列）：

- Claude Code  
- Cursor  
- Codex  

### 5.2 配置方式

- **可配置清单**，扩展已知 Agent 根。  
- **禁止**要求用户手改配置文件作为主路径。  
- **交互向导**选择根目录（可比常见 `npx/npm skills` 安装向导更省事）：  
  - 默认三件套已勾选；  
  - 主要展示「新检测到的根」供勾选/取消；  
  - 回车 = 保持当前选择。  

### 5.3 提问节奏

| 时机 | 行为 |
|---|---|
| 首次运行或配置丢失 | **自动进入向导** |
| 平时 | 静默使用已存清单 |
| 检测到新根或已选根消失 | **短问一次** |
| 非 TTY、`--yes`、或传入 `--agents` | **零提问**；缺配置则仅用默认三件套，并在报告注明「未做交互确认」 |

选择写入 **本机用户配置**（不进 git 仓库、不进 skill 正文）。具体路径实现时与现有 control / Application Support 约定对齐，本 ADR 只约束「本机、非仓库」。

## 6. Predicate contract（事实层）

### 6.1 对人说的六列（必显）

| 对人显示 | 含义 | JSON 键（稳定，供脚本） |
|---|---|---|
| 身份 | 名字、路径、内容指纹；可知时含仓库/版本 | `identity` |
| 源目录里有没有 | 全局源/物理集合中是否存在实体 | `stored` |
| 在哪个 Agent 里出现 | **按 Agent 分列**，不是单个「已分发」布尔 | `projected` |
| 控制清单是否批准启用 | 无清单时显式 `absent`，不是 `false` | `catalog_active` |
| 链接是否完好 | 投影为软链时目标是否可达、是否指回预期源 | `link_health` |
| 是否撞名/撞内容 | 同名异内容、同内容异路径、多源争用显示名 | `collision` |

### 6.2 明确不做（V1）

| 对人可能想问的 | V1 |
|---|---|
| 宿主元数据是否真能发现（超文件系统） | 统一标「暂无法判定」/`unknown` |
| 是否加载过 / 用量 | 不做 |
| 质量分 / 是否该删 | 不做（留给 hygiene） |

### 6.3 禁止字段

不得出现汇总布尔或枚举：`installed`、`ready`，或任何把未知谓词塌缩成单一绿灯的字段。

允许只读衍生字段（如缺口类），但必须由上述原子字段 **可逆推导**，并在文档写明规则。

## 7. 缺口导航（对人的八类）

Markdown 主导航 **只使用** 下列八类中文名；更细的工程状态码可留在 JSON。  
稳定英文 id（代码/对照，非对外主文案）：`complete` / `source_only` / `agent_only` / `broken_link` / `catalog_drift` / `name_collision` / `partial_projection` / `unknown`。

| 类名 | 一句含义 | 稳定英文 id |
|---|---|---|
| 齐全 | 源里有，**全部**所选且目录存在的 Agent 均有健康投影；若有控制清单则一致 | `complete` |
| 仅在源目录 | 源里有，所选 Agent 里都没出现 | `source_only` |
| 仅在 Agent | Agent 里有，对不上预期源（或源侧找不到） | `agent_only` |
| 链接损坏 | 有投影，但指向失效或非预期目标 | `broken_link` |
| 清单与现实不符 | 清单批准了但磁盘没有，或磁盘有但清单未批准 | `catalog_drift` |
| 命名冲突 | 同名不同内容，或多源争同一个显示名 | `name_collision` |
| 部分 Agent 已出现 | 源里有；所选且目录存在的 Agent 中**有的出现、有的没有** | `partial_projection` |
| 暂无法判定 | 上游收集器字段不足 | `unknown` |

**齐全定义（O9=C）：** 不得把「任一 Agent 有投影」或「部分投影」标为齐全。

**部分 Agent 已出现（第八类）：** 独立缺口位；禁止塌缩为「齐全」或笼统「暂无法判定」。链接损坏、命名冲突仍优先于本类。

**推导优先级（避免互斥混乱）：** 链接损坏 / 命名冲突 > 清单与现实不符 > 部分 Agent 已出现 > 仅在 Agent > 仅在源目录 > 暂无法判定 > 齐全。

**无控制清单特判：** 不因「没有清单」判为「清单与现实不符」；清单层标注「未使用控制清单」，条目在拓扑齐全时仍可归「齐全」。

## 8. 收集器编排与上游优化权

### 8.1 编排，不重扫

全景 **调用/复用** `skill-scan` 与 catalog/status（及同等只读收集器）的输出，只做：对齐、缺口分类、中文渲染、分诊交互。

**V1 不新增第二套磁盘遍历算法。**

### 8.2 缺字段时的行为

报告对该项写 **「暂无法判定」**，归入对应缺口类；不得猜测补全。

### 8.3 上游优化声明

若现有扫描/收集器的输出 **不够友好或信息不足**，全景实现与评审 **允许且应当** 提出对上游收集器的优化需求（补字段、改稳定键名、改善人话映射），在收集器侧落地；禁止在 panorama 内旁路重算一套「看起来差不多」的事实。

## 9. 产出物与存放

### 9.1 默认

写入本机用户数据目录（Mac 示例，实现时常量化，禁止散落魔法路径）：

```text
~/Library/Application Support/skills-refiner/panorama/
  latest.json    # 覆盖写；契约权威
  latest.md      # 覆盖写；中文渲染
  <timestamp>.*  # 可选历史；实现可裁剪保留策略
```

JSON 为权威；Markdown 不得成为第二真相源。

### 9.2 可选

| 开关（语义） | 行为 |
|---|---|
| 仅终端 | 不落盘，摘要打 stdout |
| 工作目录副本 | 显式打开才复制到 cwd（便于分享前再脱敏） |

默认 **不** 把报告写入 git 工作区。

### 9.3 Markdown 结构（高可读）

1. 总览  
2. 按八类缺口分组  
3. 按 Agent 分列摘要  
4. 文末字段对照（中文 ↔ JSON 键）  

少堆术语表；少生僻英文缩写。

## 10. 隐私

| 场景 | 策略 |
|---|---|
| 本机 `latest.*` | **真名真路径**（便于排障） |
| 可分享导出（`--share` 或等价「导出可分享」） | **脱敏副本**（弱化家目录等用户标识；技能名与指纹策略在实现说明中写清） |

不得仅靠文档「请勿提交」作为唯一防护。

## 11. 薄 skill：解说 + 分诊交互

### 11.1 深度

允许：解说地图 + **分诊路由**（下一步找谁）。  
禁止：具体突变命令；禁止在全景内直接执行 hygiene 的变更。

### 11.2 交互形态

1. **总菜单**（例如：只阅览 / 按缺口继续评估 / 调整 Agent 覆盖范围）  
2. 选「按缺口处理」后进入 **决策卡**（每类或每条）：  

| 卡片字段 | 要求 |
|---|---|
| 现状 | 一句人话 |
| 若继续，会做什么 | 说清将交给谁（如 skill-hygiene），避免误解 |
| 风险 | 无 / 低 / 中 / 高 + 半句原因 |
| 选择 | 继续评估 / 稍后再说 / 忽略此类 |

用户以选择为主，少打字。

### 11.3 选择持久化

- **默认仅当前会话有效**  
- 可选 **「记住我的选择」** 才写入本机配置  

## 12. V1 Done

全部满足才算 V1 完成：

1. 交互确认 Agent 覆盖（或命令行跳过）→ 编排现有收集器 → 写出 `latest.json` + `latest.md`。  
2. 中文报告含八类缺口导航 + 文末字段对照。  
3. JSON 含六列原子字段；无「已安装/就绪」总标签。  
4. 无控制清单时不误判「清单与现实不符」。  
5. 薄 skill 能解说 + 总菜单/决策卡；标风险；不输出突变命令。  
6. 非 TTY / `--agents` / `--yes` 可零交互跑完。  
7. 至少一组金样：人为断链、仅源未投影、清单漂移、撞名、无清单仍齐全、部分投影→「部分 Agent 已出现」。

## 13. V1 Non-goals

- 用量 / 加载率  
- 质量打分  
- 自动删除或重链  
- 默认扫描项目仓库  
- HTML 大面板作为 V1 主交付  
- 第二套磁盘遍历  
- 在全景内直接执行突变或代替 hygiene 做处置裁决  

## 14. Consequences

### Positive

- 补齐「看清本机 Skills 长相」的入口，而不稀释 hygiene/debug 职责。  
- 强制分域展示，降低「installed=true」误导。  
- 人话八类 + 决策卡降低治理门槛。  
- 编排现有收集器，避免双真相。

### Limitations

- 发现面元数据、真实 loader 行为在 V1 多为「暂无法判定」。  
- 无用量时，全景不能回答「哪些 skill 有用」。  
- 上游收集器缺口会直接表现为「暂无法判定」，依赖 §8.3 优化闭环。  
- Agent 根依赖本机布局与交互配置，CI 必须走非交互路径。

### Risks

- 若实现时叉出独立扫描逻辑，将与本 ADR 冲突——评审应否决。  
- 决策卡若滑向具体删改命令，将越权——必须以 hygiene 二次确认为界。  
- cwd 真名副本误提交——必须以可分享脱敏导出为默认分享路径。

## 15. Implementation handoff（非本 ADR 正文范围）

实现阶段建议顺序（供任务拆解，不在此展开代码）：

1. 常量与本机路径约定  
2. 编排层：调用现有 scan/status → 规范化六列  
3. 八类缺口推导（纯函数 + 金样）  
4. JSON/MD 渲染与 `latest` 覆盖写  
5. Agent 向导与非交互逃逸  
6. `skills-panorama` skill 文案与分诊卡  
7. 脱敏导出  
8. 若收集器不足 → 提交上游优化需求再继续  

## 16. Amendments

- 本 ADR 不修改 ADR-0001 的观测层级；全景 V1 不依赖 canary/用量。  
- 本 ADR 不修改 ADR-0006 的 catalog 权威定义；全景只消费其只读视图。  
- 若未来将「项目级 skills」纳入默认宇宙，须修订本 ADR 的 §4，不得静默扩大扫描范围。  
- **2026-07-22 O9=C：** §7 由七类扩为八类，新增「部分 Agent 已出现」（`partial_projection`）；齐全收紧为全部所选且存在 Agent 均有健康投影。
